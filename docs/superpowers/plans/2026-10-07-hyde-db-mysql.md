# hyde-db MySQL backend (1.1.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship MySQL 8.4 and 9.7 support in hyde-db 1.1.0: a portable MySQL apply/drop script and Markdown description, selected by the Prisma datasource provider, proven by unit, characterization, attack-suite, stop-midway and end-to-end tests.

**Architecture:** The shared core (annotations, analysis, common config rules) stays; each database is a `Dialect` held in an internal registry that `build`/`analyze` resolve from an optional `{ provider }` argument (D104, D107, D114). The MySQL apply script is ordered by safety, not by a transaction (MySQL commits DDL and grants implicitly, A74): check, build views, grant last, re-check, revoke and abort on failure (D95, D117). Aborts are failing temporary-table inserts, never routines (D99). D143 first restructures the PostgreSQL apply renderer, byte-identically, so the MySQL renderer can follow the same ordered-check-record shape.

**Tech Stack:** TypeScript (strict, ESM), Vitest 5, Testcontainers (`@testcontainers/mysql`), `mysql:8.4` and `mysql:9.7` images, Prisma 6.19.3 and 7.10.0 for end to end, Biome, pnpm, Changesets.

**Spec:** `docs/superpowers/specs/2026-10-06-hyde-db-mysql-design.md` (Approved, Gate 1 PASS, autonomy hands-off). Source of truth is `LEDGER.md`; where spec and ledger differ the ledger wins. This plan adds no decisions of its own: the choices the ledger did not settle are recorded as D148–D159. Do not edit `LEDGER.md`.

## Global Constraints

- No runtime dependencies; the package stays dependency-free (D32, D95).
- MySQL support targets the LTS lines 8.4 and 9.7 only; MySQL 8.0, innovation releases (26.x) and MariaDB are out of scope (D94, A73).
- `build(datamodel, config?, { provider? })` and `analyze(...)`: `provider` is `'postgresql' | 'mysql'`, default `'postgresql'`; 1.0 callers keep working, so the release is `minor` (D107). Public API stays `build`, `analyze` and their types (D9). Neither function ever throws on any config input (D142).
- `View.sourceSchema` is `null` on MySQL; `ResolvedConfig` gains the `mysql` member carrying `readerHost`, without `sourceSchema` and `statementTimeout`; `validateConfig(raw, dialect)` holds per-dialect key sets and limits as data (D113).
- MySQL config: `schema` (views database, default `redacted`, at most 64 characters), `role` (the account user name, default `redacted_reader`, at most 32 characters; not a MySQL `ROLE`), `readerHost` (MySQL only, default `%`); `sourceSchema` and `statementTimeout` are errors on MySQL with fix hints (D97, D120, D25, D26).
- MySQL quotes identifiers with backticks and only doubles single quotes in literals, under `SET SESSION sql_mode = 'STRICT_ALL_TABLES,NO_BACKSLASH_ESCAPES'` pinned by the script (D104, D117).
- MySQL apply order is exactly D117 (spec "Apply script", steps 1 to 9). Marker is the view `hyde_db_marker` with one column `marker` = `Generated by hyde-db` (D115). Views are created `DEFINER = CURRENT_USER` (A75). The reader account is created only when missing, `ACCOUNT LOCK`, no password; an existing account's lock state and password are never changed (D116, A85). Every `REVOKE` against the reader carries `IGNORE UNKNOWN USER` (D119, A86).
- Aborts: a failing temporary-table insert; one problem and a fix of at most 128 characters per run; no `CREATE ROUTINE`; no `DELIMITER` anywhere (D99, A76).
- MySQL drop script: marker guard (D115), absent views database is not an error (D121), drops the views database and revokes the reader's grants with `REVOKE ALL PRIVILEGES, GRANT OPTION FROM <reader> IGNORE UNKNOWN USER` (D100, D119).
- Docs (D101, D118, D120): the reader reads no table data outside the views; a refused deploy never grants the reader more than before but may leave the views rebuilt without the reader grant; the reader sees no other database names or columns (A78); only per-account resource limits stick; `mandatory_roles` non-empty is unsupported and refused; RDS and Aurora supported per provider documentation, Cloud SQL expected to work (its `mysql.*` read access unconfirmed), Azure Flexible works, PlanetScale unsupported, none tested end to end. Docs state that union types in the public API may gain members in minor releases (D112).
- Tests (D103): unit and characterization goldens for the MySQL renderers; the attack suite on MySQL 8.4 and 9.7 covering every path in A77 with pasted-fix tests; the stop-after-each-statement proof; end to end `prisma db execute` with `provider = "mysql"` on Prisma 6 and 7. Integration tests fail, never skip, without Docker (D22).
- TDD: a red test first, then the minimal code, then green. Conventional Commits. Biome lint. Coverage gate at least 95% lines and branches in `src/` (D23). Golden files change only through `pnpm golden` after a ledger-backed output change (D6); existing goldens must stay byte-identical.
- Release: a `minor` changeset for 1.1.0 (D107).
- `LEDGER.md` is never edited by implementers; cite record IDs in test names and `<!-- D.. -->` doc comments.

## Review Focus

Failure modes the spec implies but no spec section tests; each gets a test in the owning task (named below).

1. A client that runs past errors (`mysql --force`): after a refused check the later `DROP DATABASE`, `CREATE USER` and `GRANT` statements must not run, or a refused deploy would grant the reader more (and could build views inside a database hyde-db did not create). Gated statements, tested in Tasks 5, 10 and 16.
2. Hostile or unusual names and text: a backtick in a table or column name, a single quote or a backslash in a doc string or identifier, upper-case and reserved-word names. Quoting under the pinned `sql_mode` is proven in Tasks 3, 9, 10 and by an attack test in Task 14.
3. First deploy (account does not exist, so `REVOKE` needs `IGNORE UNKNOWN USER`) versus re-apply (an unlocked login survives, A85), and a re-apply after a refusal. Tasks 14 and 16.
4. Environment preconditions: no default database, default database equal to the views database, views database present without the marker, a model table named `hyde_db_marker`, a deployer without `mysql.*` read access. Tasks 6, 11, 14.
5. Edge sizes: zero visible views (only the marker view), maximum-length names (64, 32 and the `readerHost` limit) keeping every abort message within 128 characters. Tasks 5, 10, 14.
